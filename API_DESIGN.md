# API Design

## 1. Conventions

- Base path: `/api/v1`.
- JSON uses ISO 8601 UTC timestamps and string decimal values where exact decimal
  transport matters.
- Every historical read that can change with knowledge accepts an explicit `as_of`.
  “Latest” endpoints return the actual calculation cutoff in metadata.
- Responses carry `request_id`, data/config/code versions, synthetic status, and
  data-health warnings.
- Lists use cursor pagination with stable ordering.
- Expensive ingestion, calculation, event-study, and backtest operations return
  `202 Accepted` with a job resource.
- Upload and command endpoints accept an `Idempotency-Key` header.
- Errors use `application/problem+json` with stable machine codes, field errors,
  request ID, and retryability.
- OpenAPI generated by FastAPI is the contract source; a generated TypeScript client
  is checked for drift in CI.

## 2. Authentication-ready boundary

All application routes receive a `Principal` dependency. Local demo mode supplies a
named development principal; production will validate an external OIDC/JWT subject.

Policy roles:

- `viewer`: read intelligence and completed research;
- `researcher`: create studies/backtests and save experiments;
- `data_operator`: upload data and rerun calculations; and
- `admin`: activate configurations and resolve quality issues.

Audit records are emitted for every mutation. Rate limits use principal and IP,
with lower limits for uploads and research jobs.

## 3. Health and metadata

```text
GET /health/live
GET /health/ready
GET /meta/version
GET /providers
GET /providers/{code}/health
GET /instruments
GET /series
GET /configurations
```

Readiness checks database schema, Timescale extension, Redis, and required seed
catalog state. Optional providers can be degraded without making the local app
unready; their status appears in provider/data-health responses.

## 4. Ingestion

```text
POST /ingestions/files
GET  /ingestions/{batch_id}
GET  /ingestions/{batch_id}/issues
POST /ingestions/{batch_id}/normalize
POST /providers/{code}/fetches
GET  /jobs/{job_id}
```

`POST /ingestions/files` is multipart and requires:

```text
data_kind, schema_version, provider_code, dataset_code, file,
declared_source_published_at?, is_synthetic
```

The response includes batch ID, content hash, duplicate status, raw-object reference,
and normalization job link. Re-uploading identical content returns the existing batch
without duplicating raw or normalized facts.

## 5. Market, event, and positioning reads

```text
GET /market-data/bars
GET /market-data/observations
GET /series/{series_code}/observations  # planned generic series resource
GET /events
GET /events/{event_id}
GET /events/{event_id}/reaction
GET /positioning/cot
GET /positioning/snapshot
GET /market-structure/snapshot
```

Common query parameters include `instrument`, `timeframe`, `start`, `end`, `as_of`,
`provider`, `include_quality`, and cursor/limit. `as_of` affects knowledge eligibility;
`start/end` affect the observation range. They are not interchangeable.

`GET /market-data/observations` is implemented for the allowlisted public
cross-market series. It canonicalizes revisions separately for each observation
period using only versions whose `available_at` is no later than `as_of`, then
applies the per-series limit.

`POST /intelligence/calculations` takes `instrument`, `as_of`, optional configuration

is declared.

## 6.1 Implemented backtest endpoints

```text
GET  /backtests/data-range
POST /backtests/runs
GET  /backtests/runs?limit={1..50}
GET  /backtests/runs/{run_id}
```

`POST /backtests/runs` currently executes the transparent
`ASIA_RANGE_ACCEPTANCE_V1` strategy synchronously over the selected observed MT5
range. The response includes parameters, source-data hash, source-bar count,
point-in-time provenance, metrics, equity curve, and the complete trade ledger.
Longer multi-year and walk-forward jobs will use the asynchronous job contract.

## 7. Event and event-study API

Implemented endpoints:

```text
POST /api/v1/events/bundles
GET  /api/v1/events
POST /api/v1/events/surprises/calculate
GET  /api/v1/events/surprises
POST /api/v1/event-studies/runs
GET  /api/v1/event-studies/runs
GET  /api/v1/event-studies/runs/{run_id}
POST /api/v1/expectations/policy-paths/bundles
GET  /api/v1/expectations/policy-paths
GET  /api/v1/market-structure/snapshot
```

`POST /events/bundles` accepts source-versioned events with nested forecasts and
releases. Every timestamp must include a timezone. The contract rejects a
forecast whose `forecast_as_of` or `available_at` is after the original release.
Raw JSON is content-addressed and retained; normalized rows are append-only and
idempotent.

`POST /event-studies/runs` declares the release date range, explicit
`study_as_of`, XAUUSD provider, minimum importance, optional component codes, and
one mutually exclusive data mode: `REAL_ONLY` or `SYNTHETIC_ONLY`. Results return
candidate/eligible/excluded counts, reaction rows, grouped statistics, normal
approximation confidence intervals, and a SHA-256 reproducibility hash. The
current synchronous Phase 1 endpoint is bounded to three years; a queued job can
replace its transport later without changing the research contract.

## 8. Strategy-backtest API

```text
POST /backtest-experiments
GET  /backtest-experiments
GET  /backtest-experiments/{experiment_id}
POST /backtest-experiments/{experiment_id}/versions
POST /backtest-runs
GET  /backtest-runs/{run_id}
GET  /backtest-runs/{run_id}/metrics
GET  /backtest-runs/{run_id}/trades
GET  /backtest-runs/{run_id}/equity
GET  /backtest-runs/{run_id}/manifest
POST /backtest-runs/{run_id}/cancel
POST /backtest-runs/{run_id}/exports
```

Run requests reference an immutable experiment version and provide parameter values,
date/split plan, costs, slippage, latency, capital/risk, benchmark, and random seed.
Server validation rejects impossible stop/risk definitions and undocumented
look-ahead constructs.

## 9. Data health and administration

```text
GET  /data-health/summary
GET  /data-health/series
GET  /data-health/issues
GET  /jobs
GET  /audit-events
POST /data-health/issues/{issue_id}/resolve
POST /configurations/{config_id}/activate
```

Series health includes last observation period, last `available_at`, last ingestion,
expected cadence, stale deadline, timestamp precision, open issues, provider health,
and whether the series is fit for intraday, daily, or regime use.

## 10. Optional narration API

```text
POST /intelligence/snapshots/{snapshot_id}/narrations
GET  /intelligence/snapshots/{snapshot_id}/narrations/{narration_id}
```

The service receives a stored approved fact bundle, not arbitrary user facts. Output
returns sentence-to-evidence mappings and generator metadata. It cannot change the
snapshot, score, execution state, or stored deterministic insight.

## 11. Caching and consistency

- Immutable resources use strong ETags based on content hash.
- “Latest” responses use short TTLs and include snapshot ID/as-of; write jobs evict
  only affected instrument/config keys.
- Research progress can use polling first; server-sent events are an optional later
  optimization.
- API responses are committed only after all score components and lineage rows are
  in the same transaction. A partial score is never exposed as complete.

## 12. Implemented fundamental and coverage endpoints

```text
POST /api/v1/providers/public/sync
GET  /api/v1/providers/ctrader/health
GET  /api/v1/providers/ctrader/oauth/status
GET  /api/v1/providers/ctrader/oauth/start
GET  /api/v1/providers/ctrader/oauth/callback
GET  /api/v1/providers/ctrader/oauth/complete
GET  /api/v1/providers/alfred/health
POST /api/v1/providers/alfred/sync
GET  /api/v1/factors/coverage?as_of={timestamp}
POST /api/v1/fundamentals/snapshots
GET  /api/v1/fundamentals/snapshots/latest?instrument=XAUUSD
GET  /api/v1/fundamentals/snapshots/{snapshot_id}

GET  /api/v1/backtests/data-range
POST /api/v1/backtests/runs
GET  /api/v1/backtests/runs
GET  /api/v1/backtests/runs/{run_id}

POST /api/v1/events/bundles
GET  /api/v1/events
POST /api/v1/events/surprises/calculate
GET  /api/v1/events/surprises
POST /api/v1/event-studies/runs
GET  /api/v1/event-studies/runs
GET  /api/v1/event-studies/runs/{run_id}
POST /api/v1/expectations/policy-paths/bundles
GET  /api/v1/expectations/policy-paths
```

The ALFRED sync fails with HTTP 409 when `FRED_API_KEY` is absent; it never falls
back to revised current values. Policy-path uploads require complete
meeting/outcome distributions and retain raw, timestamped source records.

The cTrader OAuth start endpoint redirects only to cTrader with `accounts`
(view-only) scope. Its callback validates a signed, expiring browser transaction,
exchanges the one-minute code, stores only authenticated ciphertext, clears the
transaction cookie, and redirects to a clean completion URL. Health and status
responses never return client credentials, authorization codes, or tokens.

`GET /market-structure/snapshot` accepts `instrument`, optional `provider_code`,
optional timezone-aware `as_of`, mutually exclusive `AUTO`/`REAL_ONLY`/
`SYNTHETIC_ONLY` modes, chart timeframe, and source-bar limit. `AUTO` prefers one
real provider and falls back to one synthetic provider; it never mixes the two.
The response includes six timeframe states, the provider session-template version,
session ranges/completeness, chart bars, rules/config, data hash, and fully
traceable detections.

`POST /backtests/runs` accepts `strategy_mode` as either
`PRICE_ONLY_CONTROL` or `FUNDAMENTAL_ALIGNED`, plus minimum score, coverage, and
confidence thresholds. Responses expose mechanical-candidate counts, permission
and rejection counts/reasons, per-candidate audit decisions, combined data hashes,
and full fundamental evidence on accepted trades.
